简化Baseline建议：与主实验保持一致的物理模拟
===============================================================================

当前问题：
-----------
Baseline使用了更复杂的picking_up/serving两阶段模型，而主实验只有serving一个阶段。
这导致：
1. 车辆位置更新逻辑复杂
2. 状态管理复杂
3. 难以与主实验公平对比

建议方案：
-----------
将Baseline的车辆状态管理简化成和主实验完全一样：

### 1. 简化 assign_order()
```python
def assign_order(self, vehicle_id, order, current_time, pickup_time_minutes=0.0):
    if vehicle_id not in self.vehicles:
        return False

    vehicle = self.vehicles[vehicle_id]
    if vehicle['status'] != 'idle':
        return False

    # 简化：直接变serving，不分picking_up阶段
    vehicle['status'] = 'serving'
    vehicle['assigned_order'] = order
    vehicle['order_start_time'] = current_time
    vehicle['pickup_time_minutes'] = pickup_time_minutes
    vehicle['service_time_minutes'] = self._calculate_travel_time(
        order.get('grid_index'),
        order.get('dest_grid_index')
    )
    vehicle['total_completion_time'] = pickup_time_minutes + vehicle['service_time_minutes']
    vehicle['idle_since'] = None

    return True
```

### 2. 简化 update_serving_vehicles()
```python
def update_serving_vehicles(self, current_time):
    completed_orders = []
    cancelled_orders = []

    for vehicle_id, vehicle in self.vehicles.items():
        if vehicle['status'] != 'serving':
            continue

        order = vehicle.get('assigned_order')
        if not order or not vehicle.get('order_start_time'):
            continue

        elapsed_minutes = (current_time - vehicle['order_start_time']).total_seconds() / 60.0

        # 检查是否完成
        if elapsed_minutes >= vehicle.get('total_completion_time', 0):
            order['status'] = 'completed'
            completed_orders.append(order)

            # 完成服务：车辆瞬移到目的地（和主实验一样）
            dest_grid = order.get('dest_grid_index', vehicle['current_grid'])
            self.complete_service(vehicle_id, dest_grid, current_time)

    return completed_orders, cancelled_orders
```

### 3. 车辆位置更新
- 匹配时：位置不变（和主实验一样）
- 服务中：位置不变（和主实验一样）
- 完成时：瞬移到目的地（和主实验一样）

优点：
------
1. 与主实验物理模拟完全一致
2. 代码更简单，更容易维护
3. 可以公平对比（唯一区别是调度策略）
4. 不需要处理复杂的接驾途中取消等边缘情况

缺点：
------
1. 物理模拟不如picking_up/serving两阶段真实
2. 但主实验也是这样的，所以这不是问题

建议：
------
采用此简化方案，让baseline和主实验的环境逻辑完全一致。
