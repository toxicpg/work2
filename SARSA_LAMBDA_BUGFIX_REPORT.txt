BUG #1: 变量作用域问题 (已修复)
----------------------------------------
位置: run_simulation_phase() 函数, 第 497-546 行
问题: idle_vehicles_list 只在 if ticks % 10 == 0 块内定义,
      但在块外被 agent.update_sarsa() 使用,导致变量未定义错误

修复前:
```python
if ticks % 10 == 0:
    idle_vehicles_list = [...]  # 只在这里定义
    ...
# 块外使用
state_key = agent.get_state_hash(saa_time_slot, idle_vehicles_list)  # ❌ 错误
```

修复后:
```python
# 每个 tick 都获取车辆分布
idle_vehicles_list = [...]  # 移到外面

if ticks % 10 == 0:
    ...  # 使用 idle_vehicles_list 进行调度

# 块外使用
state_key = agent.get_state_hash(saa_time_slot, idle_vehicles_list)  # ✅ 正确
```

影响: 严重 - 会导致运行时 NameError
状态: ✅ 已修复


BUG #2: 探索半径计算错误 (已修复)
----------------------------------------
位置: run_simulation_phase() 函数, 第 514 行
问题: 探索时计算的半径 max(5, int(3 * 0.6)) = max(5, 1) = 5
      比原始半径 3 还大,违背了"更保守"的设计意图

修复前:
```python
original_radius = agent.max_dispatch_radius  # = 3
agent.max_dispatch_radius = max(5, int(original_radius * 0.6))  # = max(5, 1) = 5 ❌
```

修复后:
```python
original_radius = agent.max_dispatch_radius  # = 3
agent.max_dispatch_radius = max(1, int(original_radius * 0.6))  # = max(1, 1) = 1 ✅
```

影响: 中等 - 探索策略不符合预期,但不会崩溃
状态: ✅ 已修复
